# 방문·활동 분석

관리 > 방문·활동 분석(`/admin/analytics`)에서 조회합니다. 서버가 Users의 is_admin을 검증하며 비로그인은 401, 일반 사용자는 403을 받습니다.

- NEXT_PUBLIC_MODE=live에서 브라우저가 경로 이동과 탭 선택을 수집합니다. 데모에서는 자동 수집하지 않습니다.
- 로그인 성공·실패, 로그아웃, 인증 상태 확인(me)을 제외한 RPC 성공·실패는 서버에서 기록합니다. 기존 AuditLog의 변경 이력도 표시합니다.
- Supabase km_audit_log의 기존 id/data 구조를 사용합니다. Activity 행의 detail에는 허용한 메타데이터만 저장합니다. 추가 테이블 마이그레이션은 없습니다.
- 비로그인은 서버가 서명한 임의 방문자 쿠키(7일)로 구분합니다. 세션 쿠키는 조회 이벤트 때 연장되며 30분 비활동 시 새로 발급됩니다. 로그인 계정은 서명된 인증 쿠키로 확인합니다.
- 원문 IP, 원문 User-Agent, URL 쿼리, 검색어, 로그인 입력 이메일/코드, 요청·응답 본문은 수집하지 않습니다. 기기·브라우저 유형과 외부 유입 호스트만 저장합니다. 기존 감사 로그의 원문 detail도 분석 API에 반환하지 않습니다.
- 로그인 실패는 계정을 인증할 수 없으므로 익명으로 기록합니다. 로그인 성공 이후 동일 방문자/세션으로 이동 경로를 조회할 수 있습니다.
- UTC 기준 최대 31일 범위, 10,000건 단위로 이어서 조회합니다. 통계·검색·CSV는 현재 불러온 기록 기준입니다. 더 불러오기 또는 기간을 좁혀 전체 기록을 분석할 수 있습니다.
- CSV는 스프레드시트 수식 주입을 방지합니다. 화면은 상세 로그 50건씩 페이지를 나눕니다.
- 기록은 응답 이후 Next.js after에서 저장합니다. 3초 타임아웃이나 DB 장애는 로그를 누락시킬 수 있으나 사용자의 작업 결과를 실패로 바꾸지 않습니다. 로그 저장 오류는 Vercel 로그에 고정 메시지로 남습니다.
- 브라우저 차단·오프라인·쿠키 삭제로 누락/방문자 중복이 있을 수 있습니다. 익명 클라이언트 이벤트는 보안 감사 증거가 아닙니다. 수집 API는 허용 이벤트 검증과 출처 검증, 인스턴스별 분당 120건 제한을 적용합니다. 전역 분산 rate limit은 아닙니다.
- 과거 방문 기록은 소급 생성하지 않습니다. 기존 감사 로그는 보유한 범위만 조회됩니다. 자동 삭제는 하지 않으며 별도 보존 정책이 필요하면 기간과 삭제 범위를 먼저 정해야 합니다.

검증: `node --test tests/activity.test.mjs tests/mentoring.test.mjs`, `npm run build`.
